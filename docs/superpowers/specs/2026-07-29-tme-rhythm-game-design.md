# TME 节奏派对 · 设计文档（Design Spec）

- 版本：v2.0（场景化重构）
- 日期：2026-07-29
- 场景：TME 24h AI 黑客松 —— 音乐小游戏课题
- 一句话：借鉴《节奏天国》"靠听不靠看、极简操作、角色剧场"的灵魂，让 TME 十周年 IP 家族当节奏舞台的表演者，音乐真正驱动画面与判定。

---

## ⚠️ v2.0 重构说明（当前实现，覆盖下文 v1.0 的部分决策）

用户反馈：v1.0 的"两轨抽象点击"太像传统下落音游、缺乏趣味，要求对齐《节奏天国》的**场景化任务**，并强化视觉设计。据此重构：

### 变更 1：抽象点击 → 场景化动作（核心）
节拍不再是"轨道上的音符"，而是**世界里的具体动作**。每首曲目 = 一个主题场景，共用同一套"逼近 → 到拍 → 出手 → 表演反馈"内核（换皮不换骨）：

| 曲目 | 场景 | 动作 | IP |
|---|---|---|---|
| 霓虹脉冲 | 🏃 跨栏闯关 | 光环冲到面前时跳过去 | 🐧 QQ音乐 |
| 赛博狂潮 | 🔨 疯狂敲钉 | 钉子冒头时一锤砸下 | 🐕 酷狗 |
| 午夜留声 | 🗡️ 音浪切片 | 音符宝石飞来时挥刀斩断 | 🐦 全民K歌 |

### 变更 2：事件模型 lane → action
谱面事件从 `{time, lane}` 改为 `{time, action:'go'|'hold'|'trap', dur?}`。
- `go`：到拍出手；`hold`：蓄力长按；
- `trap`（假动作陷阱）：**不出手才是完美**，出手判 miss。

### 变更 3：难度按"技能"分层（不是堆数量）
- `EASY 跟拍`：正拍全 go，建立节奏感；
- `NORMAL 卡点`：切分节奏 + hold 蓄力；
- `HARD 炫技`：密集卡点 + trap 假动作（考 impulse control）。
（灵感来自参考 skill 的核心原则：难度 = 有意义的权衡 / 考不同技能，而非单纯加量。）

### 变更 4：单键 + 防乱按
操作收敛为唯一"出手"键（空格/点击）；空挥（窗口内无目标却按）直接断连击，杜绝乱按刷分。

### 变更 5：视觉 = 扁平可爱角色 + 霓虹演唱会舞台
调和"《节奏天国》趣味"与用户要的"炫酷冲击"：角色是扁平 blob + IP 徽章，舞台是霓虹扫射灯束 + 透视滚动地板 + 粒子/镜头抖动/屏闪 + squash/stretch 表演。

### 代码结构变更
- 新增 `src/render/stage.js`（共享舞台）、`src/render/scenes/{base,runner,whack,slice,index}.js`。
- `src/core/engine.js` 重写为场景驱动；`judge.js` 加 `breakCombo`；`data/tracks.js` 产出 `{music,duration,charts,meta}`。
- 弃用 `src/render/renderer.js`、`src/render/character.js`（旧两轨版，保留在磁盘但不再引用）。

> 以下 v1.0 内容保留作为设计脉络参考；凡与本节冲突处，以本节为准。

## 0. 课题对齐（Why）

对应课题五个考核点：

| 课题要求 | 本方案如何满足 |
|---|---|
| 玩法真正与音乐结合（非背景音） | Web Audio `AnalyserNode` 实时频谱分析，低频能量驱动背景/角色/判定圈律动；谱面即音乐节拍 |
| 降低理解和操作门槛 | 极简 1–2 键（Tap/Hold），收缩节拍环 + IP 角色预备动作做视觉提示 |
| 创意与落地闭环 | 纯 Web + 手机模拟器外壳，浏览器即玩，24h 可交付可演示版本 |
| 分享/排行/挑战/多人 | 成绩海报一键分享、seed 挑战链接、本地排行榜（留后端接口） |
| 商业化潜力 | IP 皮肤养成、新歌"玩即宣发"、会员解锁高难谱、看广告复活 |

## 1. 设计取舍（核心决策，已定）

1. **玩法哲学 = 节奏天国式，不是太鼓/osu 式。**
   - 不做高速下落音符轨道（会退化成"看谱反应"，同质化）。
   - 做极简 Tap/Hold（进阶 Flick），靠"听感 + 角色动作 + 节拍音效"预判出手。
2. **谱面双轨（调和"程序生成"与"手工谱面"两个选择）。**
   - **手工谱面**：内置 3 首 IP 歌曲，JSON 精编 —— 核心体验，演示主力。
   - **自动生成器**：onset 检测自动出谱 —— 差异化亮点（"随便丢首歌就能玩"），做到"能用但不完美"，不是重点。
3. **技术栈 = 纯 Web**（HTML5 Canvas + Web Audio API + 原生 JS，Vite 起本地服务）。
   - 竖屏 9:16 设计，网页里套**手机模拟器外壳**（notch/圆角/状态栏），电脑体验如同手机。
   - 架构预留 PWA / Capacitor 口子，后续可打包成 App，无需重写。

## 3. 系统架构（模块划分）

单一职责、可独立测试的模块：

```
tme-rhythm-game/
├─ index.html                # 入口 + 手机外壳容器
├─ vite.config.js
├─ src/
│  ├─ main.js                # 启动、屏幕路由（选曲→游戏→结算）
│  ├─ core/
│  │  ├─ conductor.js        # 音频时钟：唯一权威时间源，节拍同步
│  │  ├─ analyser.js         # Web Audio AnalyserNode 封装，输出频段能量
│  │  ├─ beatmap.js          # 谱面数据结构、加载、校验
│  │  ├─ generator.js        # 自动谱面生成（onset 检测）
│  │  ├─ judge.js            # 判定逻辑（Perfect/Good/Miss、combo、分数）
│  │  └─ engine.js           # 游戏主循环，串起 conductor/judge/renderer/fx
│  ├─ render/
│  │  ├─ renderer.js         # Canvas 绘制：舞台/判定圈/节拍环/HUD
│  │  ├─ fx.js               # 粒子、闪光、combo 弹跳、频谱律动
│  │  └─ character.js        # IP 角色状态机与动画帧
│  ├─ ui/
│  │  ├─ shell.js            # 手机模拟器外壳
│  │  ├─ songselect.js       # 选曲 + 难度 + 上传自选音乐
│  │  └─ result.js           # 结算：评级、分享海报、排行榜
│  ├─ data/
│  │  ├─ songs.js            # 歌曲清单（音频路径、BPM、offset、谱面路径）
│  │  └─ beatmaps/*.json     # 手工谱面
│  └─ assets/                # 音频、IP 图、音效
└─ docs/superpowers/specs/   # 本文档
```

### 模块契约（关键）

- **conductor.js** —— 时间的唯一真相
  - 输入：`AudioContext`、音频 buffer/element。
  - 输出：`getTime()`（当前歌曲播放秒数，用 `AudioContext.currentTime` 校准，**不要用 `requestAnimationFrame` 累加计时**，会漂移）。
  - 职责：play/pause/seek，提供 `songTime` 给判定和渲染对齐。

- **beatmap.js** —— 谱面即数据
  - 结构：
    ```json
    {
      "songId": "demo1",
      "difficulty": "normal",
      "offset": 0.12,
      "notes": [
        { "time": 1.20, "type": "tap",  "lane": 0, "ip": "penguin", "fx": "spark" },
        { "time": 2.00, "type": "hold", "dur": 0.8, "lane": 1 },
        { "time": 3.50, "type": "flick","lane": 0 }
      ]
    }
    ```
  - `time` 单位秒（歌曲时间轴）；`lane` 0–1 对应屏幕左/右两个出手位（极简，贴合节奏天国 1–2 键哲学）。

- **judge.js** —— 判定与计分
  - 判定窗口（可调）：Perfect ±45ms / Good ±90ms / 超出=Miss。
  - 计分：Perfect=100，Good=50，Miss=0；Combo 倍率随连击提升；评级 S(≥95%)/A(≥85%)/B(≥70%)/C。
  - 纯函数化：输入 `(noteTime, hitTime)` → 输出判定级别，便于单测。

- **analyser.js** —— 音乐驱动特效的数据源
  - 输出：`bass`(低频能量 0–1)、`mid`、`treble`、`energy`(整体包络)。
  - 供 fx.js 和 character.js 每帧读取，实现"画面随音乐动"。

- **generator.js** —— 自动谱面（亮点，能用即可）
  - 输入：解码后的 `AudioBuffer`。
  - 算法（简版 onset 检测）：对音频分帧做 FFT → 计算相邻帧频谱能量差（spectral flux）→ 取超过动态阈值的局部峰值 → 峰值时间点即 note。
  - 后处理：最小间隔去抖（如 <120ms 合并）、按能量强弱决定 tap/hold。
  - 输出：与手工谱面同结构的 `beatmap`，直接喂给引擎。
  - 明确接受"不完美"：慢歌可能空、快歌可能密，够展示"任意歌自动出谱"即可。

## 4. 玩法细节

### 4.1 屏幕布局（竖屏 9:16）
```
┌───────────────┐  ← 手机外壳(notch/状态栏)
│  分数  Combo   │  HUD
│               │
│   [IP 舞台]    │  主打角色随节奏律动
│               │
│    0     1     │  两个出手位(lane)
│    ◎     ◎     │  判定圈 + 收缩节拍环
│  ─── 判定线 ─── │
│  [Tap/Hold 触区]│  触控/点击区
└───────────────┘
```

### 4.2 出手提示逻辑
- note 到来前约 0.6–0.8s，对应 lane（左/右）上出现**收缩的节拍环**，并触发该 lane IP 角色的**预备动作**。
- 环缩到判定圈瞬间即最佳出手点（Perfect）。
- 听觉为主：重拍有节拍音效；视觉环仅作辅助，降低门槛。

### 4.3 操作
- **Tap**：点对应 lane（左/右）。
- **Hold**：按住到尾拍松手，全程角色持续动作，松手判定尾。
- **Flick**（进阶/高难）：快速上滑，高潮爆发段。
- 电脑端键位映射：`F / J`（或 ←/→）→ 左/右两 lane，鼠标/触屏点击左右触区。

### 4.4 难度
- 每首歌 Easy / Normal / Hard 三份谱面（自动生成也分三档密度阈值）。
- 递进：密度↑、Hold/Flick 占比↑、连打段、判定窗口收窄。
- 关卡内正反馈：Combo 越高背景越炸、角色越嗨；Miss 掉 Combo 明显挫败反馈。

## 5. 特效（引人入胜）

- **音乐律动层**（全程，手工谱也用）：背景/判定圈/角色随 `analyser` 低频脉冲呼吸。
- **命中反馈**：Perfect 白闪 + 粒子绽放 + 角色 hit 庆祝帧；Good 小反馈；Miss 角色 miss 帧 + 屏幕轻微暗。
- **Combo**：数字弹跳放大，里程碑(50/100)全屏特效。
- **Full Combo / 结算**：IP 家族集体庆祝动画 + 评级揭晓 S/A/B/C 动态。
- 实现用 Canvas 2D 粒子池（对象复用，防 GC 卡顿），60fps 目标。

## 6. 社交 & 商业化

### 6.1 社交传播
- **成绩海报**：结算页 `canvas.toDataURL()` 生成图片（分数+评级+主打 IP 角色+歌名），一键保存/分享。
- **挑战链接**：URL 带 `?song=xxx&diff=hard&seed=xxx`，好友打开同曲同难同谱比拼。
- **排行榜**：先 `localStorage` 本地榜，抽象 `LeaderboardService` 接口留后端。

### 6.2 商业化模型（写进产品说明）
- **IP 皮肤养成**：打歌攒星币解锁/抽取 IP 角色皮肤、贴纸、庆祝特效。
- **玩即宣发**：新歌上线即做成关卡，用户玩的过程就是听新歌，可做品牌联名限定关。
- **会员**：解锁 Hard 谱面、独占 IP 皮肤、去广告、专属结算特效。
- **广告**：Miss 后看广告复活续命、结算看广告分数翻倍。

## 7. 手机模拟器外壳（你要的体验）

- `shell.js` 渲染一个手机外框（圆角、notch、底部指示条、状态栏时间/电量假 UI）。
- 游戏 Canvas 固定在框内 9:16 区域，外部背景做虚化/渐变。
- 提供"切换设备边框"（iPhone/Android 视觉）非必需，P3。
- 打包路径：项目按 PWA 组织（manifest + service worker 可选），后续 `Capacitor` 包壳即成 App，同一套代码。

## 8. 24h 交付切分（里程碑）

| 优先级 | 内容 | 产出判定 |
|---|---|---|
| **P0 骨架** | 手机外壳 + 竖屏 Canvas + conductor 音频时钟 + 1 首内置歌 + Tap 判定 + Combo/分数 HUD | 能跟着 1 首歌卡点打，出分 |
| **P1 音乐驱动** | analyser 频谱 → 背景/判定圈/角色律动 | 肉眼可见画面随音乐动 |
| **P1 IP 舞台** | 主打 IP 角色 idle/hit/miss + 全连庆祝 | 角色有反馈 |
| **P2 完整** | 3 首歌 × 3 难度、Hold（Flick 视情况）、选曲界面、结算海报 | 完整体验闭环 |
| **P3 亮点** | 自动生成器（上传自选音乐出谱）、挑战链接、本地排行榜 | "随便丢首歌能玩"可演示 |

> 时间紧时的取舍：优先保 P0+P1+P2 的"3 首内置歌爽感闭环"，P3 自动生成器做到"能演示一次"即可，Flick 可砍。

## 9. 技术风险与对策

| 风险 | 对策 |
|---|---|
| 音画不同步（判定飘） | conductor 用 `AudioContext.currentTime` 做权威时钟；每首歌加 `offset` 手调对齐；不要用 rAF 累加计时 |
| 自动谱面质量差 | 定位为"亮点非核心"；做去抖后处理；演示选一首鼓点清晰的歌 |
| 移动端音频延迟/自动播放限制 | 用户手势后再 `AudioContext.resume()`；预解码音频；校准输入延迟补偿 |
| Canvas 掉帧 | 粒子对象池、离屏缓存静态元素、控制粒子上限 |
| 版权 | 黑客松用无版权/自制/授权片段，或短 demo 片段 |

## 10. 明确不做（YAGNI）

- 不做真正的多人实时联机（只做异步 seed 挑战）。
- 不做账号系统/云存档（本地即可，留接口）。
- 不做复杂关卡编辑器（谱面手写 JSON）。
- 不做 3D、不引游戏引擎框架。
- 不做真实支付（商业化只在产品说明里阐述）。
